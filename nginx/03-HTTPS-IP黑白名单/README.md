# 03-HTTPS-IP黑白名单

## 示例目标

本示例只研究 Nginx 入口层配置，不额外创建应用代码。配置演示 HTTP 跳转 HTTPS、TLS 终止、请求头传递，以及管理入口的 IP 白名单和普通入口的 IP 黑名单。

## 核心原理

### HTTPS 与 TLS 终止

端口 `80` 只负责把客户端跳转到 HTTPS。端口 `443` 完成证书验证和 TLS 握手，再把解密后的 HTTP 请求转发给内部 Node 服务。这样证书和加密策略可以集中在 Nginx 管理。

配置只允许 TLS 1.2 和 TLS 1.3，并使用会话缓存减少重复握手成本。HSTS 会让浏览器长期只使用 HTTPS，正式启用前必须确认站点和所有子资源始终支持 HTTPS。

### IP 白名单与黑名单

管理入口 `/admin/` 先列出允许的地址，最后 `deny all`，属于默认拒绝策略。普通入口只拒绝示例恶意网段，其他来源允许访问。

如果 Nginx 前面还有 CDN、云负载均衡器或其他代理，必须先限制可信代理并恢复真实客户端 IP，否则访问控制看到的只是代理地址。

## 使用步骤

1. 打开 [nginx/nginx.conf](nginx/nginx.conf)。
2. 将 `CERT_ROOT` 替换为真实证书目录，并确认 Nginx 能读取证书、不能向无关用户暴露私钥。
3. 将示例白名单和黑名单网段替换为实际地址。
4. HTTPS 代理示例指向 Node1 的 `3201`，IP 控制示例还会使用 Node3 的 `3203`；可以配合任务二启动服务。
5. 先执行配置检查，再加载配置，并保留独立管理通道防止误封自己。

## 验证方法

- 请求 HTTP 域名，确认返回 HTTPS 永久跳转并保留路径和查询参数。
- 使用受信任证书访问 HTTPS，检查协议版本和转发后的应用响应。
- 从允许地址请求 `/admin/`，确认可以访问；从其他地址请求应返回拒绝。
- 修改黑名单为测试客户端地址后访问普通入口，确认规则按顺序生效。
