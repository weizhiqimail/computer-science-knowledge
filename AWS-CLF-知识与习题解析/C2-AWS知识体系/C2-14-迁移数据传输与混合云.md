# C2-14-迁移、数据传输与混合云

> 资料口径说明：本章延续当前 AWS CLF-C02 学习项目既有规则，主要依据用户提供的 719 题题库、`chatGPT会话1.md`、`chatGPT会话2.md`、`cmd1.md` 与前序 C2 章节的结构整理。题库中的答案与评论用于识别高频考点、业务场景和易混项，不自动视为当前 AWS 官方结论。涉及会随时间变化的产品状态、考试范围与 Support 体系时，本章只沿用项目资料中已经明确记录的状态；正式考试前仍应再对照 AWS 当前官方页面。


## 1-本章目标

真实企业迁移 AWS 不是“把服务器复制过去”这么简单，而是先回答：

```text
我现在到底有哪些服务器和应用？
迁移是否值得？
应用怎么迁？
数据库怎么迁？
PB 级数据怎么迁？
在线传输还是离线设备？
迁移过程怎么跟踪？
迁移后本地机房是否继续存在？
```

项目资料把迁移主线整理为：

```text
Discover  → Application Discovery Service
Evaluate  → Migration Evaluator
Server    → Application Migration Service
Database  → DMS / SCT
Track     → Migration Hub
Offline   → Snow Family
```

题库还经常把 DataSync、Storage Gateway 与这些服务混在选项中。

## 2-迁移前：Discovery-与-Assessment

## 3-★★★-AWS-Application-Discovery-Service

**正式名称：** AWS Application Discovery Service
**中文：** 应用发现服务

### 3.1-为什么需要它

大型企业可能连自己有多少服务器、服务器依赖关系和资源使用情况都没有完整清单，无法直接制定迁移波次。

### 3.2-它是什么

Application Discovery Service 用于收集本地环境服务器配置、使用情况和依赖信息，帮助迁移规划。

### 3.3-GlobalShop-场景

GlobalShop 先盘点旧机房 500 台服务器，识别哪些应用彼此依赖。

### 3.4-常见组合

Discovery data → Migration planning / Migration Hub。

### 3.5-容易混淆

Discovery Service 不负责真正复制服务器；Application Migration Service 才是服务器迁移执行方向。

### 3.6-题库通常怎么考

discover on-premises servers、dependencies、inventory before migration → Application Discovery Service。



## 4-★★★-Migration-Evaluator

**正式名称：** Migration Evaluator
**中文：** 迁移商业评估服务

### 4.1-为什么需要它

企业决定迁移前需要评估当前基础设施使用情况、成本和迁云商业价值。

### 4.2-它是什么

Migration Evaluator 帮助建立数据驱动的 business case 和迁移成本/资源评估。

### 4.3-GlobalShop-场景

GlobalShop 财务与架构团队评估本地机房未来 3 年成本与迁 AWS 的潜在收益。

### 4.4-常见组合

Discovery / inventory data → Migration Evaluator → business case。

### 4.5-容易混淆

Migration Evaluator 关注评估，不负责实际迁移工作负载。

### 4.6-题库通常怎么考

business case、TCO assessment、evaluate migration economics → Migration Evaluator。



## 5-★★★★-AWS-Application-Migration-Service

**正式名称：** AWS Application Migration Service
**中文：** 应用/服务器迁移服务

### 5.1-为什么需要它

企业需要把本地或其他云中的服务器工作负载迁移到 AWS，希望减少手工重建服务器的工作。

### 5.2-它是什么

Application Migration Service（MGN）用于把受支持的源服务器持续复制到 AWS，并在切换时启动 AWS 上的实例。

### 5.3-GlobalShop-场景

GlobalShop 把旧 Java Application Server 从本地 VM 迁到 EC2。

### 5.4-常见组合

On-Prem server → replication → staging → EC2 cutover。

### 5.5-容易混淆

Application Migration Service ≠ DMS。前者迁服务器/应用；DMS 迁数据库数据。

### 5.6-题库通常怎么考

lift-and-shift servers、migrate applications/servers to EC2 → Application Migration Service。



## 6-★★★★-AWS-Database-Migration-Service

**正式名称：** AWS Database Migration Service
**中文：** AWS 数据库迁移服务

### 6.1-为什么需要它

数据库迁移如果停机数天影响业务，需要持续复制变更并尽量缩短切换停机。

### 6.2-它是什么

DMS = Database Migration Service，用于迁移数据库数据，并支持同构或部分异构数据库迁移场景。

### 6.3-GlobalShop-场景

GlobalShop 从本地 MySQL 迁到 Amazon RDS/Aurora，在迁移期间持续复制增量变更。

### 6.4-常见组合

Source DB → DMS replication → Target DB。

### 6.5-容易混淆

DMS 迁数据；Schema Conversion Tool 处理异构引擎时的 Schema/代码转换评估和转换。

### 6.6-题库通常怎么考

migrate database、minimal downtime、ongoing replication → DMS。



## 7-★★★-AWS-Schema-Conversion-Tool（SCT）

SCT = Schema Conversion Tool。

当数据库引擎不同，例如 Oracle → PostgreSQL，Schema、Stored Procedure、SQL 方言可能不同。

```text
DMS
→ 搬数据

SCT
→ 转换/评估 schema 与 database code
```

不要把二者当成完全替代关系。

## 8-★★★★-AWS-DataSync

**正式名称：** AWS DataSync
**中文：** 在线数据传输与同步服务

### 8.1-为什么需要它

企业需要在本地存储与 AWS S3/EFS/FSx 等之间高速、自动化传输大量文件或对象数据。

### 8.2-它是什么

DataSync 是在线数据传输服务，自动处理传输、校验、调度等工作。

### 8.3-GlobalShop-场景

GlobalShop 把本地 NAS 的数百 TB 商品图片逐步同步到 S3。

### 8.4-常见组合

On-Prem storage → DataSync Agent/service → S3/EFS/FSx。

### 8.5-容易混淆

DataSync ≠ DMS：DataSync 搬文件/对象存储数据；DMS 搬数据库。DataSync ≠ Snow：DataSync 依赖网络在线传输，Snow 可离线物理设备。

### 8.6-题库通常怎么考

online data transfer、NFS/SMB storage to S3/EFS/FSx、automated transfer → DataSync。



## 9-★★★★-AWS-Snow-Family

**正式名称：** AWS Snow Family
**中文：** AWS 离线/边缘数据传输设备家族

### 9.1-为什么需要它

当数据量巨大、网络带宽不足或传输窗口很短时，通过 Internet 上传 PB 级数据可能需要几个月。

### 9.2-它是什么

Snow Family 提供物理设备把大量数据运送到/从 AWS，并存在边缘计算相关能力。题库中 Snow Family 粗略曝光约 14 次。

### 9.3-GlobalShop-场景

GlobalShop 关闭旧数据中心前，把 PB 级历史归档数据复制到 Snow 设备后寄回 AWS 导入 S3。

### 9.4-常见组合

On-Prem data → Snow device → shipping → AWS → S3。

### 9.5-容易混淆

Snow ≠ DataSync：Snow 是离线/物理运输路线；DataSync 是在线网络传输。

### 9.6-题库通常怎么考

petabyte-scale offline migration、limited bandwidth、physical device → Snow Family。



## 10-★★★-AWS-Migration-Hub

**正式名称：** AWS Migration Hub
**中文：** 迁移项目跟踪与集中视图

### 10.1-为什么需要它

迁移项目可能同时使用 MGN、DMS、合作伙伴工具，企业需要一个中心位置跟踪应用迁移状态。

### 10.2-它是什么

Migration Hub 提供迁移发现、规划和跟踪相关集中视图。

### 10.3-GlobalShop-场景

GlobalShop 迁移 PMO 在一个中心查看各应用迁移波次和工具状态。

### 10.4-常见组合

Discovery/Migration tools → Migration Hub。

### 10.5-容易混淆

Migration Hub 不负责实际复制所有数据，它更偏迁移项目可视化和协调。

### 10.6-题库通常怎么考

track migration progress、central migration dashboard → Migration Hub。



## 11-Storage-Gateway-在迁移与-Hybrid-中的位置

Storage Gateway 已在 C2-04 详细讲。这里重新放入迁移图，只强调：

> 它更适合长期 Hybrid Storage 接入，不是“一次性把所有数据迁完就结束”的唯一工具。

项目资料特别记录：FSx File Gateway 当前产品状态已变化，旧题库仍可能出现；因此要区分 CURRENT 与 LEGACY 题目语境。

## 12-★★★-AWS-Transfer-Family

Transfer Family 提供托管的文件传输协议端点，例如 SFTP/FTPS/FTP 等，把传统文件交换工作流连接到 S3/EFS。

如果题目强调“继续使用 SFTP 客户端/协议，但后端放 S3”，不要误选 DataSync。

## 13-迁移策略：7-Rs-的理解

项目 C2 不要求把迁移策略背成口号，但应知道常见思路：

- Rehost：Lift and Shift；
- Replatform：适度优化平台；
- Refactor / Re-architect：重构；
- Repurchase：换 SaaS/产品；
- Relocate：整体环境迁移类场景；
- Retain：暂时保留；
- Retire：下线。

真正决策取决于业务价值、风险、时间与技术债。

## 16-本章最后要形成的判断方式

不要把本章记成一串 AWS 产品名，而要形成下面的思考路径：

```text
业务需求是什么？
        ↓
它属于哪一层问题？
        ↓
需要什么技术能力？
        ↓
哪些 AWS 服务提供这类能力？
        ↓
为什么某一个更贴合场景？
        ↓
其他相似服务为什么不合适？
```

真正稳定的考试能力不是“看到关键词就背答案”，而是能够从业务要求推导到技术能力，再从技术能力推导到 AWS 服务。
